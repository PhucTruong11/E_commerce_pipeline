# Ngày 01 · Nền tảng, bootstrap và ingestion

> Ngày 2026-10-23. Mục tiêu học tech thông qua commercial analytics. Đây là **plan thực hành và code mẫu**, chưa phải kết quả triển khai. Lượt hiện tại chỉ viết plan, rà scaffold rồi commit/push GitHub; chưa cài dependencies, tạo DB/roles, sửa platform hoặc chạy DAG.

## 1. Cuối buổi cần hiểu và làm được gì?

Giải thích và kiểm chứng được đoạn đầu của luồng:

```text
4 CSV read-only
    → validate + inventory
    → bootstrap PostgreSQL một lần
    → extract một snapshot nhất quán
    → DuckDB Bronze + đối soát
```

Đầu ra chính: contract đầu vào, runtime tối thiểu và đủ 4 bảng Bronze có lineage. Chỉ tick từng đầu ra sau khi thực thi và kiểm chứng. Nếu hạ tầng chưa sẵn sàng, dừng ở contract/runtime và ghi blocker; không coi plan là pipeline đã chạy.

dbt Silver/Gold, báo cáo insight, dashboard và CDC là các bước sau. Cuối buổi hôm nay chỉ cần thống nhất định nghĩa sales/profit/margin và biết câu hỏi nào sẽ trả lời từ dữ liệu này.

## 2. Kiến thức cần nắm

| Concept | Hiểu bằng bài toán này | Tự giải thích lại |
| --- | --- | --- |
| Grain và key | row_id là khóa ứng viên của sales line; order_id cần xác nhận scope | Vì sao không dedup theo order_id + product_code? |
| OLTP / OLAP | PostgreSQL giữ nguồn; DuckDB phục vụ phân tích | Mỗi engine chịu trách nhiệm gì? |
| Data contract | Headers, encoding, types, null, PK/FK và metric meaning | Parser cấu trúc chưa kiểm tra điều gì? |
| Transaction | Bootstrap 4 bảng cùng commit/rollback | File thứ tư lỗi thì ba bảng đầu thế nào? |
| Idempotency | Retry không nhân đôi hoặc reset nguồn đã có giao dịch mới | Bootstrap khác refresh như thế nào? |
| Consistent snapshot | Đọc 4 bảng qua một PG transaction repeatable-read | Tại sao 4 connection riêng có thể lệch snapshot? |
| Batch extraction | Fetch từng batch từ source, ghi vào candidate DuckDB | Fetchmany khác giữ toàn DataFrame trong RAM ra sao? |
| Lineage / reconciliation | bootstrap_id, extraction_id, counts và totals | Chứng minh Bronze không mất/nhân dòng bằng gì? |
| Docker / orchestration | Image chứa code/deps; volumes giữ file; Airflow gọi command | Container thoát thì DuckDB còn ở đâu? |

## 4. Chặng B · profile trước khi chọn schema

Inventory đã có: customer 17.415, sales 51.290, product 28.356, region 3.828 dòng. Đã kiểm tra headers/width và candidate keys; chưa xác nhận toàn bộ semantic.

File dự kiến viết: **scripts/profile_csv.py**. Hàm dưới đây chỉ gom inventory từ parser đã có; không tự kiểm tra type/FK hoặc chốt grain nghiệp vụ.

```python
from pathlib import Path
from ingestion.sources.csv_contracts import CONTRACTS, read_checked_csv

def build_inventory(input_dir: Path):
    inventory = []
    for table in CONTRACTS:
        # Parser kiểm tra header, số cột, key và hash đúng payload đã đọc.
        # Không in records vì customer chứa dữ liệu cá nhân.
        records, metadata = read_checked_csv(input_dir / f"{table}.csv", table)
        inventory.append(metadata)
        del records
    return inventory
```

Lưu inventory JSON vào vùng reports/ local đã ignore. Khi bootstrap, phải đọc/validate/hash cùng payload sẽ load; không tin một inventory cũ trong khi CSV đã đổi.

Những kiểm tra tiếp theo:

- **Mã định danh:** giữ text, không để mất số 0 đầu; kiểm tra whitespace/null markers.
- **Ngày:** xác nhận format thực tế trước khi parse; ghi min/max và số lỗi, không tự đoán locale.
- **Tiền/discount:** Decimal/numeric, xác nhận dấu phân cách và scale; phân biệt null với zero.
- **FK:** sales → customer/product/region; đo số orphan, không âm thầm bỏ bằng inner join.
- **Order grain:** kiểm tra customer/date/segment trong một order; thêm region nếu dùng làm thuộc tính cấp đơn.
- **Product identity:** product_code unique chưa đủ khẳng định một mã là một SKU nghiệp vụ.
- **Commercial semantics:** sales gross/net, profit gồm chi phí gì, currency có nhất quán không? Nếu chưa biết, ghi rõ chưa xác nhận.

File ghi quyết định dự kiến: **docs/data-contract.md**. Chỉ thêm khi có kết quả profiling, nêu rõ verified/assumed/open thay vì điền mặc định cho đủ.

## 6. Chặng D · bootstrap CSV → PostgreSQL

Các file sẽ viết:

| File | Vai trò |
| --- | --- |
| infra/postgres/init/010_source_schema.sql | 4 bảng typed trong e_commerce + bootstrap inventory |
| scripts/bootstrap/load_csv.py | CLI bootstrap; validate, guard, transaction, ledger |
| ingestion/sources/csv_contracts.py | Giữ parser hiện có, bổ sung contract đã chốt |

Tên đề xuất: database ecom_source_dev; writer ecom_owner; extractor ecom_reader. Chưa provision. Mỗi connection phải kiểm tra đúng database/user; không dùng superuser LaplapTech hoặc metadata Airflow.

Mẫu helper đích: **scripts/bootstrap/load_csv.py**. Đầu vào typed_rows là tuples đã convert theo contract, đúng thứ tự headers. Helper chỉ COPY một bảng, **không phải bootstrap hoàn chỉnh**; caller phải guard, kiểm ledger và bao cả 4 bảng + metadata trong cùng transaction.

```python
from psycopg import sql
from ingestion.sources.csv_contracts import CONTRACTS

def copy_source_table(cur, table, typed_rows):
    # CONTRACTS là allowlist; identifiers không ghép bằng f-string SQL.
    if table not in CONTRACTS:
        raise ValueError("Unknown source table")
    columns = CONTRACTS[table][1]
    statement = sql.SQL("COPY {} ({}) FROM STDIN").format(
        sql.Identifier("e_commerce", table),
        sql.SQL(", ").join(sql.Identifier(column) for column in columns),
    )
    with cur.copy(statement) as copy:
        for values in typed_rows:
            copy.write_row(values)
```

write_row dùng COPY protocol row-by-row; không thêm FORMAT CSV vào helper này. Lỗi trong transaction phải rollback toàn bootstrap, gồm ledger. [Psycopg COPY](https://www.psycopg.org/psycopg3/docs/basic/copy.html).

Quy tắc caller cần có:

- Source mới/rỗng đúng contract mới được seed; source có dữ liệu nhưng thiếu ledger thì refuse để kiểm tra, không tự reset.
- Cùng fingerprint bootstrap: skip load; nguồn có thể đã có OLTP changes, nên không so CSV để ghi đè nguồn.
- Fingerprint khác: yêu cầu workflow new-baseline riêng, không tự TRUNCATE.
- DDL/migrations phải kiểm tra schema hiện hữu, không dùng IF NOT EXISTS để che schema mismatch.
- Không commit password/DSN; không log nguyên customer record khi có lỗi.

Checkpoint: đủ 4 bảng, counts/keys hợp lệ, thử retry và lỗi ở bảng thứ tư bằng synthetic fixture để chứng minh rollback. Không thử reset dữ liệu thật chỉ để chạy test.

## 7. Chặng E · PostgreSQL → DuckDB Bronze

File dự kiến viết: **ingestion/loaders/postgres_to_duckdb.py**. Dùng ecom_reader và một connection autocommit=True; bên trong mở transaction repeatable-read read-only cho đủ 4 bảng.

```python
# File đích: ingestion/loaders/postgres_to_duckdb.py
from psycopg import sql
from ingestion.sources.csv_contracts import CONTRACTS

def extract_snapshot(pg_conn, write_batch):
    # Caller guard identity và tạo candidate DuckDB/DDL trước.
    with pg_conn.transaction():
        pg_conn.execute(
            "SET TRANSACTION ISOLATION LEVEL REPEATABLE READ, READ ONLY"
        )
        for table, (_, headers) in CONTRACTS.items():
            statement = sql.SQL("SELECT {} FROM {}").format(
                sql.SQL(", ").join(sql.Identifier(c) for c in headers),
                sql.Identifier("e_commerce", table),
            )
            with pg_conn.cursor(name=f"extract_{table}") as cur:
                cur.execute(statement)
                while True:
                    rows = cur.fetchmany(1000)
                    if not rows:
                        break
                    write_batch(table, rows)
```

PostgreSQL repeatable-read cho các SELECT trong transaction cùng thấy snapshot ổn định; COUNT/totals đối soát cũng phải lấy trong transaction đó. Snippet chưa có reconciliation, DuckDB callback hoặc error cleanup. [Transaction isolation](https://www.postgresql.org/docs/16/transaction-iso.html).

Callback sẽ ghi vào candidate mới bằng parameterized insert, Bronze DDL tường minh và metadata extraction_id; giữ decimal/date theo contract. Không append nhiều snapshots vào fact input, không dùng checksum CSV làm identity của nguồn PG đã thay đổi.

Một project file lock giữ suốt extract → dbt → publish; Airflow concurrency 1 không bảo vệ writer CLI bỏ qua lock. Đóng connection DuckDB của loader trước khi gọi dbt subprocess. Chưa publish báo cáo từ Bronze.

Nếu dbt chưa triển khai hôm nay, chỉ nghiệm thu candidate Bronze. Mẫu data flow của các bước Silver/Gold/publish nằm trong [ingestion plan](../ingestion-plan.md), không đánh dấu đã chạy.

## 8. Mẫu commercial SQL cho buổi kế tiếp

File dự kiến: **warehouse/analyses/q01_sales_profit.sql**. SQL dưới đây chỉ chạy khi fct_order_lines có thật, null policy/currency/period đã chốt và quality tests đạt; không phải query có thể chạy trong scaffold hiện tại.

```sql
-- Grain đầu vào: một row_id, không phải một đơn hàng.
-- sales được gọi là source-reported, chưa tự gắn nhãn gross/net.
SELECT
    COUNT(*) AS sales_line_count,
    SUM(sales) AS source_reported_sales,
    SUM(profit) AS source_reported_profit,
    SUM(profit) / NULLIF(SUM(sales), 0) AS profit_margin
FROM marts.fct_order_lines;
```

Không lấy AVG margin theo dòng để thay ratio of sums. Chưa xác nhận tiền tệ thì không kết luận so sánh tài chính xuyên thị trường. Đơn lỗ cần SUM(profit) cấp order < 0, không đếm mỗi dòng lỗ thành một đơn.

dbt target sẽ là DuckDB candidate với [dbt-duckdb](https://github.com/duckdb/dbt-duckdb), models đọc Bronze đã extract, không query trực tiếp PostgreSQL nguồn.
